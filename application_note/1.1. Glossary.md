<h2 id="1.1">1.1 Glossary</h2>

<a href="#Table1.1">Table 1.1</a> shows the terms related to the operation of IPL explained in this application note.

<h4 id="Table1.1">Table 1.1 The term for IPL operation</h4>

<table>
<colgroup>
<col style="width: 27%" />
<col style="width: 72%" />
</colgroup>
<thead>
<tr>
<th>Term</th>
<th>Description</th>
</tr>
</thead>
<tbody>
<tr>
<td>Initial Program Loader<br>
(IPL)</td>
<td><p>A loader program that launches an FSP Application for the RZ/A3 environment.</p>
<p>It is called from the BootROM program to initialize the memory and the peripheral I/O modules installed in boards, then copies the FSP application and jumps to the copy destination according to the application header.<br>
IPL is developed based on Arm Trusted Firmware and it is equivalent to BL2 of Arm Trusted Firmware.<br>
When changing the Flash memory to be used, the user is requested to create and add the initialization code according to the specifications of the Flash memory to be used, referring to this application note.
</p></td>
</tr>
<tr>
<td>BootROM Program</td>
<td>The BootROM program is the program that executes first after the device starts, and it copies the next boot program from the memory associated with the boot mode to the On-chip RAM and jumps to the next boot program.<br>
IPL is premised on operation in Boot Mode 3 (1.8-V Serial Flash Memory) or Boot Mode 4 (3.3-V Serial Flash Memory) and IPL written to the Serial Flash memory is copied to the specified address (H'0001_2000) of the On-chip RAM and the boot process is executed.<br>
This program is stored in the RZ/A3's internal ROM, so it does not need to be created by the user.</td>
</tr>
<tr>
<td>FSP Application</td>
<td>This is a program consisting of BSP and sample programs to use the functions implemented on the board.</td>
</tr>
<tr>
<td>Application Header</td>
<td><p>A header placed at the beginning of the FSP application, used by IPL to refer to the destination address or entry point address of the FSP application.<br>
Before executing IPL, the FSP application image including the application header must be written to the specified address of the Flash memory.</p>
<p>The write destination address of the Application Header can be changed in IPL build option, and the default is H'2002_0000.</p></td>
</tr>
<tr>
<td>Serial Flash memory driver</td>
<td><p>The Serial Flash memory driver creates parameters for executing operations that comply with the specifications of the Serial Flash memory and manages the execution order of operations.</p>
<p>This driver is implemented with specifications that depend on the Serial Flash memory.</p>
<p>If you use a Serial Flash memory other than the AT25QL128A (Product of Renesas Electronics) supported by the default IPL, you need to change driver according to the specifications.</p></td>
</tr>
<tr>
<td><p>OctaFlash Memory driver</p>
<p>/ OctaRAM driver</p></td>
<td><p>The OctaFlash memory driver and OctaRAM driver create parameters for executing operations that comply with the specifications of each memory and manage the execution order of operations.</p>
<p>These drivers are implemented with specifications that depend on each memory.</p>
<p>If you use the OctaFlash memory and OctaRAM other than the MX66UW1G45G (OctaFlash memory, product of Micronics) and APS51208N (OctaRAM, product of AP Memory) supported by the default IPL, you need to change drivers according to the specifications.</p></td>
</tr>
<tr>
<td>Manual Mode</td>
<td><p>This is the operation mode of the SPI Multi I/O Bus Controller.</p>
<p>In this mode, data is read / written by sending Read and Write commands to the Serial Flash memory via serial communication.<br>
The default operating mode of the SPI Multi I/O Bus Controller is Manual Mode.</p></td>
</tr>
<tr>
<td>External Address Space Read Mode</td>
<td><p>This is the operation mode of the SPI Multi I/O Bus Controller.</p>
<p>In this mode, the device can read data by performing read access to the address space where the Serial Flash memory is mapped.<br>
This mode is enabled by switching the operation mode from Manual Mode.</p></td>
</tr>
<tr>
<td>Configuration Mode</td>
<td><p>This is the memory access mode of the Octa Memory Controller.</p>
<p>In this mode, data is read / written by sending Read and Write commands to the OctaFlash memory and OctaRAM via serial communication.<br>
Both Configuration Mode and Memory-map Mode can be used in Octa Memory Controller without switching the operation mode.</p></td>
</tr>
<tr>
<td>Memory-map Mode</td>
<td><p>This is the memory access mode of the Octa Memory Controller.</p>
<p>By using this mode, the device can read / write data by performing read / write access to the address space where OctaFlash memory and OctaRAM are mapped.<br>
Both Configuration Mode and Memory-map Mode can be used in Octa Memory Controller without switching the operation mode.</p></td>
</tr>
</tbody>
</table>
